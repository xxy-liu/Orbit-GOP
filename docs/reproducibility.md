# Reproducibility boundary

The portable S3–S5 implementation is included: model definitions, locked training configuration, the three fixed views, gradient-derived functional signatures, dGOP, predicted-class q_func, evidence calibration, all-method scoring, metrics and confirmatory analysis code. The candidate also retains selected historical result artefacts and provenance. Historical archive executors are not distributed in the public release.

R0 repository/data structure, R1 syntax/import/static checks and R2 minimal synthetic CPU functional checks are **VERIFIED** for this candidate. R2 checks do not use source datasets or checkpoints. R3 complete paper reproduction is **NOT PROVIDED BY THIS RELEASE**. The original nine trained weights, original per-sample score arrays and complete original 5,000-replicate bootstrap outputs are not included; source datasets must be obtained independently. Historical final-figure execution is not supplied as a complete portable pipeline. A new training/evaluation run produces new evidence and does not by itself recover the exact frozen weights or scores.

The confirmatory code path is `prepare_run` → nine `train_confirmatory` runs → paired `evaluate_confirmatory` runs → `analyze_confirmatory`. `prepare_run` locks inputs for a new run, not the historical freeze. The analysis entry requires complete score arrays and writes new output in a separate `ORBIT_RUN_DIR`. Its `--help` path performs no analysis. [`show_tables`](../scripts/reproduce_tables/show_tables.py) only prints already saved tables.

Historical S0–S2 numerical evidence is reported within its original development scope. Saved Figure 4–9 coordinates and historical table outputs are evidence artefacts, not raw per-sample measurements or a guarantee of byte-identical final figure regeneration. [Historical archive scope](HISTORICAL_ARCHIVE_SCOPE.md) explains the source exclusion, and [figure mapping](FIGURE_SOURCE_MAPPING.md) maps final paper numbering to the retained sources. The original Full Orbit view reproduction `FAIL` field remains in the retained historical CSV; a later approved FP32 publication authority is documented separately at [`results/historical/main_table5/FINAL_VIEW_ABLATION_PUBLICATION_AUTHORITY.md`](../results/historical/main_table5/FINAL_VIEW_ABLATION_PUBLICATION_AUTHORITY.md). No failure status was rewritten.

The paper execution record and this candidate's release checks are distinct. The recorded confirmatory environment includes Python 3.10.10, torch 2.11.0+cu128, torchvision 0.26.0+cu128 and CUDA 12.8. The current release checks exercised CPU paths with those package versions; no wheel installation, CUDA paper replay, dataset download, training or bootstrap was performed. The historical FP32 efficiency setting has its own [environment record](environment.md).

For access to absent checkpoint, reference or score artefacts, contact the corresponding author listed in [CITATION.cff](../CITATION.cff), stating the manuscript title, backbone, seed, target table or figure and the required hashes. Availability and transfer permissions must be confirmed by the rights holder. Dataset access and redistribution follow source terms; [datasets.md](datasets.md) lists official acquisition routes. An identity hash is not a downloadable artefact.
